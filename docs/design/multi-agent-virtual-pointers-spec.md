# 多子智能体共享电脑与虚拟指针｜开发规格单

**实施分支：** `cyble`，基线 `0e5841e`。**下游编码模型：** DeepSeek V4.1 Flash。
本文定义实现与验收；所列待验证项不是当前版本已具备的能力。

> 多鼠标模式默认关闭；以下指针派出、常驻、动作联动及回收要求均适用于显式开启多鼠标模式期间。后续用户确认的 desktop/page_* 入口、主思考框与子 Agent 审计布局，以及本轮实现/测试进展见[当前实施账本](<cyble-multi-mouse-implementation-plan.md>)。本文引用的“现有”代码与行号是基线审查快照，不是本轮完成声明。

## 任务目标

让同一 DSH Desktop 会话树中的子 Agent 共享一台 Windows 电脑。直接或嵌套子 Agent 一派出，就从真实鼠标当前位置分出自己的指针，自动获得名称和可辨颜色；即使从未调用电脑工具，也在整个存活期显示。结束时，虚拟指针回到用户当时的真实鼠标位置，再消失。根 Agent 不增加虚拟指针。

尽可能同时操作：**同一窗口按到达顺序串行；不同窗口在确证安全时并行。** 若实际输入不能安全并行，仍要同时显示各 Agent 的指针和各自的指向，不出错优先于吞吐。共享桌面仍只有一套真实鼠标、键盘和输入焦点。

## 输入定义

- **宿主身份与生命周期：** 来自 DSH 实际工具执行上下文的调用者身份、Agent 存活状态以及根／子关系。以运行时身份为内部键，不以展示名、调用顺序或模型传参识别。
- **桌面动作与目标：** 复用现有桌面工具参数。坐标动作以该 Agent 的截图／视口为基准；运行时绑定目标顶层窗口及其有效版本、动作顺序和取消信号。
- **真实指针位置：** 分身和回收时读取系统当前鼠标位置。只读，不从 Overlay 写回系统光标。
- **运行状态：** 现有桌面模式、按应用策略、用户授权和紧急停止状态；本规格不新增权限。

## 输出定义

- **用户可见：** 一个逻辑指针覆层，显示所有存活子 Agent 各自的指针、名称、颜色和位置。标记在普通桌面应用之上，不抢焦点、不拦截真实点击；重叠时展开而不改变实际操作坐标。
- **工具结果：** 保留现有工具接口和结果结构，明确区分排队、已执行／已确认、已投递但效果未验证、拒绝、取消，以及中断后结果不确定。排队、已投递或预览动画都不代表目标应用已执行。
- **审计：** 能将动作归属到正确 Agent 和目标窗口，并区分等待、执行和最后结果。动画不写成真实鼠标操作。

## 环境约束

- 目标与端到端验收环境是 **Windows 上的 DSH Desktop**，不是 DSH Web。只覆盖普通交互桌面；UAC／安全桌面和独占全屏不在置顶保证内。不引入独立桌面、虚拟机或额外管理员权限。
- [plugin.ts:53–72](<../../src/plugin.ts#L53-L72>) 当前通过宿主 MCP 客户端启动 stdio 服务。已查的 MCP 客户端转发工具名和参数，现有链路不会自动把 caller Agent 交给下游。实际 Desktop 加载的版本和注册链路须先验证；不能把 `tools/execute` 的信号调整能力当成改写身份或参数的能力。
- [computer.ts:76–83](<../../src/computer.ts#L76-L83>) 与 [desktop.ts:76–100](<../../src/desktop/desktop.ts#L76-L100>) 现有控制器包含共享的当前目标、模式与截图上下文；需分离 Agent 私有状态和共享桌面状态。[driver.ts:41–64](<../../src/desktop/driver.ts#L41-L64>) 的 pending Map 只关联请求与回复；[win32.ps1:1307–1315](<../../src/desktop/win32.ps1#L1307-L1315>) 的现有读取与执行循环是串行的。并发提交 Promise 不等于并行输入。
- 优先复用 [overlay.ts](<../../src/desktop/overlay.ts>) 的单实例管理及 [windows-takeover.cs:361–468](<../../scripts/windows-takeover.cs#L361-L468>) 的绘制能力。思考窗的 30 秒 idle／20 秒 linger 及单一 activity owner 不是指针生命周期；不改变思考窗和审计窗已有行为。

## 功能清单

1. **可信身份（开工门槛）。** 在 DSH Desktop 实际运行链路确认：能否在本插件的工具执行入口取得可信 caller，并把身份与每一笔请求绑定后传到本地控制器；以及派出、终止和恢复时能否通过宿主生命周期和子 Agent 归属契约识别同一个 Agent。用实际 `agent/created`、`agent/disposed` 和 `subagents.rootOf` 等宿主契约核对时序，不用名字或 ambient initiator 单独推断归属。若现有 MCP 桥没有受支持的身份传递点，先验证宿主正式扩展点能否让本插件拥有该执行入口，同时保留注册、审批、结果投影与取消。没有可信路径，停止受阻实现并报告具体缺口，不启用多 Agent 路由。功能启用后，无法确认身份的调用不得退回根 Agent 执行。
2. **派出、常驻、回收。** 派出时采样真实鼠标并立即登记标记，不等首次工具调用、不阻塞 Agent 创建等待动画；直接和嵌套子 Agent 都登记，根 Agent 不登记。思考、等待、空闲或跑普通工具均不隐藏。终止时不再接收该 Agent 的新动作，取消待执行动作；指针回到回收时实时的真实位置（鼠标在动时用最新采样收尾），只移除该 Agent 的标记。初始化失败、取消、卸载、明确关闭桌面控制或整个覆层时清理；重载时与宿主存活状态核对，不复活旧标记。仅关思考窗不等于关虚拟指针。
3. **视觉与坐标。** 自动分配同屏唯一可读的名称及可辨的指针颜色；存活期间标识保持稳定，近似颜色要以轮廓、形状或标签辅助分辨。多个标记同起点或交叉时展开标签或错位展示，保留共同真实坐标的指向，不改变命中点。每个标记按自己的桌面动作更新；输入排队时也能分别显示其指向，但不可表现为已点击。多显示器、混合 DPI 与负屏幕坐标使用同一套明确的转换，覆层不截获用户输入、不挡既有紧急停止控件。
4. **隔离目标与截图。** 每个 Agent 独立持有窗口选择、截图、缩放／坐标转换和依赖这些状态的动作顺序。动作在入队时绑定目标与坐标基准，执行前复核窗口存活、句柄是否复用及相关视口是否变化。遇到目标变化或基准失效，要求重新截图，不把旧坐标投给新窗口。动作及其结果截图按同一目标一致性处理；若不能保障，说明需重新观察，不能把其他 Agent 的变化当成本动作成效。
5. **窗口级仲裁。** 在控制器受理时确定可追踪的到达顺序。同一窗口上的动作，包括前台和后台路径，均按该顺序执行；不得因异步预检或优先级插队。将同一交互上下文内可能互相影响的子控件、所有者窗口和弹窗并为同一冲突范围，不能只因 HWND 数值不同就并行。一次点击、组合键、按下至释放的拖动等作为完整动作处理。只有不同冲突范围、实际执行链与目标应用均已证明隔离的后台动作才允许并行；安全的只读观察和准备工作尽量并行。凡经同一控制器触发原生输入的入口都遵守仲裁。
6. **全局排他与降级。** 前台真实输入，以及依赖共享焦点、剪贴板、模式切换或其他全局资源的动作走共享排他通道；必要时与窗口级输入互斥，不让两层锁各自放行导致冲突。收敛到固定的资源获取顺序。不确定是否独立或 helper 不支持并行时，输入串行，指针仍各自显示；这不授权切前台。
7. **停止、拒绝与恢复。** 遵循现有按应用策略和紧急停止语义。后台不支持即停止该动作并说明原因；若要接管真实输入，必须走原用户授权流程。排队取消后不发送输入；运行中按可用取消点安全收尾，超时不能当作已停止。未确认旧操作收尾前，不放行冲突输入；已投递或结果不确定的动作不自动重放。宿主或 helper 重连要拒绝旧代请求／标记，不能接着执行旧队列。

## 非功能约束

- **正确性优先：** 后台调度和覆层都不得移动真实鼠标、抢占焦点。针对已知不兼容的窗口继续失败即停；不以模拟输入投递成功冒充应用响应。
- **资源可控：** 复用单实例 helper 和覆层，不为每个 Agent 常驻进程或轮询器。队列、动画及重试有界；忙时给明确结果，不静默丢动作。停止、异常与重载不留悬挂锁、按键、监听器或幽灵指针。
- **兼容与隐私：** 不修改模型可见工具参数来携带身份。保留既有单 Agent、按应用策略、思考窗／审计窗和专用浏览器工具语义。日志只留排障所需的身份、目标和时序，不写凭据或完整的输入内容。

## 测试验证标准

| 验收项 | 通过条件 |
| --- | --- |
| A1 · 派出与常驻 | DSH Desktop 同时派出至少两个直接子 Agent 和一个嵌套子 Agent，根无额外标记。各子 Agent 首次工具调用前就可见；一个从不操作电脑、空闲超过思考窗收起时间的子 Agent 仍可见。初始化失败、快速派出／结束、重载后无残留或重复标记。 |
| A2 · 视觉与回收 | 同起点、密集重叠和应用切换时仍能读出每个名称；覆层在普通应用之上且鼠标可穿透。验证多显示器／DPI／负坐标映射。让用户在回收前及回收中移动鼠标，结束的标记回到当前真实位置，只移除该标记，其他指针不受影响。 |
| A3 · 路由与隔离 | 根、直接及嵌套 Agent 的交错调用正确归属。模型传入其他 Agent 的 ID 不会改写身份。两 Agent 分别选择不同窗口、缩放和截图，之后的坐标仍各自命中；关闭或替换窗口后旧动作不发送。 |
| A4 · 实际并行与顺序 | 用可记录事件和时序的两个普通测试窗口：同一窗口以受理序收到完整且不交错的动作；独立且获证支持的窗口要在执行端证明动作重叠，而非只看调用同时发出。不能证明安全的路径记录原因并验证串行降级，同时两个指针仍分别可见。 |
| A5 · 不干扰与拒绝 | 无人操作时记录后台点击、拖动、无点击移动与回收期间的真实光标和前台窗口，排除异常中途变化；前台仅在授权后执行且确认排他。复验至少一个已知后台不兼容应用（如 Java/AWT）：动作拒绝、审计一致，无前台或命令回退。 |
| A6 · 停止与恢复 | 覆盖排队和执行中取消、紧急停止、超时、helper 重启及窗口失效。无错投、重复输入、残留按键、悬挂锁或成功误报。 |
| A7 · 回归 | 运行相关自动化测试、`npm run typecheck`、`npm run build` 与 `npm test`。在 DSH Desktop 实测上方置顶、单 Agent 操作、思考窗／审计窗和策略未回退。用桌面画面或窗口枚举验证覆层；只截目标窗口不能证明覆层未出现。 |

## 禁止事项

- 不得改宿主安装或配置来规避身份或审批限制；不得用模型可填的 `agentId`、最近 Agent、activity owner 或异步时序做身份路由。不得绕过原有审批、输出投影、取消或紧急停止。
- 不得把虚拟指针当成多套 Windows 真实输入，不得用动画驱动系统鼠标。后台操作失败时不得自行切前台，也不得改用 shell、CLI、脚本、DOM／API 等路径代替本应通过鼠标键盘完成的操作。原有专用浏览器功能不是后台失败的兜底。
- 不得为了并行牺牲同窗顺序、目标校验或失败即停；不许以 mock、调用时间重叠或 DSH Web 代替 Desktop 实机验收。不扩展到安全桌面或独占全屏。
- 不得硬编码凭据、引入额外权限、改无关功能、覆盖他人工作或擅自提交／推送。

## 交付要求

1. **先给可行性结论：** 在 `cyble` 上记录实际 DSH Desktop 的派出／终止和身份绑定证据、已验证的输入执行路径，以及可并行与必须串行的边界。身份门槛未过时，报告具体契约缺口与受影响项，不交假实现；未证实输入并行时，保留视觉同时、串行输入的方案。
2. **再交最小实现：** 通过前置验证后，先交生命周期、绘制与隔离，再交输入仲裁及已获证的并行路径。复用现有架构与工具，附必要的单测和可重复的桌面验证步骤，不改 DSH 安装。
3. **最后交验收表：** 逐项填写 A1–A7 的通过／失败／未验证、环境和版本、关键观察及尚未覆盖的限制。自动化、源码核查和 DSH Desktop 实测分别标记。
